# Atlas 架构

## 产品边界

Atlas 将大模型视为“提出交易意图的非确定性组件”，而不是持有账户控制权的执行器。真实订单必须通过本地确定性执行链路。

```text
行情与新闻 -> Agent 推理 -> 结构化交易意图 -> 风控规则 -> 订单执行器 -> 交易所
                                  |             |
                                  +-- 审计日志 --+
```

## 进程模型

- Renderer：React 工作台，只负责展示和用户交互
- Preload：暴露最小白名单 API，不提供任意文件或进程能力
- Main：窗口生命周期、加密凭证、本地数据库、交易所与模型适配器
- Worker：后续用于 Agent 调度、行情归一化、回测和订单状态机

## 交易所接入

首批适配 Binance Spot Testnet，随后通过统一接口支持 OKX、Bybit 和 CCXT 兼容交易所。账户权限拆分为行情读取、账户读取、现货交易、合约交易；提币权限永不暴露给 Agent。

## 模型接入

模型适配器采用 OpenAI 兼容协议，可连接 CCSwitch、本地模型或第三方模型 API。每次调用记录模型、提示词版本、工具输入、结构化输出、耗时与成本。下单输出必须通过 JSON Schema 校验。

## 风控闸门

风控在模型之外独立执行：

- 单笔最大风险和仓位
- 账户与策略日内最大回撤
- 组合净敞口和相关性限制
- 最小风险回报比
- 预估滑点、订单频率和最小流动性
- 止损必填和价格偏离保护
- 全局紧急停止

## 迭代顺序

1. 完成本地数据库、Binance Testnet 签名请求和订单状态机
2. 接入 CCSwitch 实际推理和结构化工具调用
3. 增加策略版本、回测、Paper Trading 和回放
4. 增加真实子账户审批流、通知和可观测性
5. 签名、公证、自动更新与发布渠道
